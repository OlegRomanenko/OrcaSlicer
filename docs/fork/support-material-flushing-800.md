# Материал поддержки: продувка 800/800 мм³

## Назначение и границы

Увеличить автоматически рассчитываемую продувку при переходах на материал поддержки и обратно.
Основной сценарий: PLA для модели и PETG с включённым признаком «Материал поддержки» на Bambu Lab A1 mini.
Расчётный объём очистки должен передаваться в штатный сброс при смене материала, не расходоваться
на деталь, её заполнение, поддержки или башню очистки.

Доработка использует существующий признак `filament_is_support`. Назначение филамента для печати поддержек
само по себе не заменяет этот признак. Сравнение `filament_type` и общее правило для разных типов пластика
в область доработки не входят.

## База и способ переноса

- Апстрим: <https://github.com/OrcaSlicer/OrcaSlicer.git>, ветка `main`.
- Базовая ревизия: `bd1304443cb417d39c7be7d4182d8d8c1f737908`.
- Ветка форка: `v2.5.0-lora`.

В [FlushVolCalc.cpp][code:flush-calc] задать следующие значения общих констант:

| Константа | Значение, мм³ |
| --- | ---: |
| `g_flush_volume_to_support` | 800 |
| `g_min_flush_volume_from_support` | 800 |

Изменение общих констант распространяется на все профили принтеров, использующие этот расчёт,
а не только на A1 mini. Новые настройки, внешние зависимости, изменения форматов, профилей принтеров
и штатного G-code смены материала не требуются.

Потребители, которые необходимо сверять при переносе после обновления апстрима:

- `WipingDialog::CalcFlushingVolumes()` в [WipeTowerDialog.cpp][code:flush-dialog] — полный пересчёт матрицы.
- `Sidebar::auto_calc_flushing_volumes_internal()` в [Plater.cpp][code:plater] — автоматическое обновление
  переходов для изменённого филамента.
- Расчёт матрицы в [OrcaSlicer.cpp][code:cli] — путь CLI.

Переносить значения по смыслу констант и их потребителей, а не по совпадению номеров строк.
Если апстрим изменит порядок применения коэффициента или направление продувки, повторно проверить
контракт ниже; одной замены чисел в таком случае недостаточно для подтверждения совместимости.

## Требуемое поведение

Значения относятся к внутренней матрице `flush_volumes_matrix` до применения `flush_multiplier`.
Под цветовым расчётом понимается существующая оценка для пары филаментов с её штатными поправками.

| Переход между разными слотами | Значение внутренней матрицы, мм³ |
| --- | --- |
| Обычный материал → материал поддержки | Ровно 800, независимо от цвета |
| Материал поддержки → обычный материал | Максимум из цветового расчёта и 800 |
| Материал поддержки → другой материал поддержки | Ровно 800: правило назначения имеет приоритет |
| Обычный материал → обычный материал | Штатный расчёт без изменений |

Диагональ матрицы при полном пересчёте остаётся нулевой. Расчёт по цветам, исключение виртуальных смешанных
филаментов, коэффициент и ручное редактирование матрицы сохраняют существующее поведение.
Сохранённые в проектах или введённые вручную значения не нужно принудительно переписывать:
новые значения применяются при пересчёте матрицы.

Для сценария A1 mini множитель должен быть `1.0`: тогда целевой расчётный объём составляет 800 мм³
при переходе на материал поддержки и не менее 800 мм³ обратно. При коэффициенте меньше единицы
он уменьшается; например, `800 × 0.3 = 240 мм³`. Эта доработка не вводит абсолютный минимум после
коэффициента и не меняет его значение по умолчанию. В диалоге матрица отображается уже с учётом коэффициента.

## Передача объёма в сброс на A1 mini

`WipingExtrusions::mark_wiping_extrusions()` в [ToolOrdering.cpp][code:tool-ordering] возвращает весь
переданный объём без распределения в модель, если предыдущий или следующий филамент имеет
`filament_is_support`. Это ограничение должно сохраняться в обоих направлениях перехода.

В Bambu-ветке `Print::_make_wipe_tower()` в [Print.cpp][code:print] продувка `purge_volume` передаётся
отдельно от объёма заполнения башни. Через `WipeTower::plan_toolchange()` и результат смены материала
в [WipeTower.cpp][code:wipe-tower] она поступает в `WipeTowerIntegration::append_tcr()`
в [GCode.cpp][code:gcode]. Там объём переводится в длину филамента `flush_length`
и порции `flush_length_1`–`flush_length_4`.

Штатный [профиль A1 mini 0.4][profile:a1-mini] использует эти значения в `change_filament_gcode`:
в команде `M620.10 A1` с параметром `L[flush_length]` и в блоках `FLUSH_START` / `FLUSH_END`
с командами экструзии `G1` с параметром `E`. Профили сопел 0.2, 0.6 и 0.8 наследуют этот код смены материала.
Это путь сброса при смене филамента; последующее заполнение башни является отдельной операцией.

При проверке количества учитывать штатную поправку на загрузку: профиль задаёт `grab_length = 17.4` мм,
а слайсер вычитает `17.4 × 2.4 = 41.76 мм³` как объём, уже выдавленный при загрузке.
Для расчётных 800 мм³ при множителе 1.0 в явные порции продувки передаётся 758.24 мм³.
Остальные 41.76 мм³ учитываются как продувка при загрузке, а не как расход на модель или башню.
Физическое выполнение загрузки относится к поведению прошивки: проверка исходников и G-code
подтверждает передачу расчётного объёма, но не заменяет измерение фактической экструзии.

## Проверка доработки и совместимости с апстримом

Автоматическая регрессия [test_flush_vol_calc.cpp][test:flush-limits] в наборе `libslic3r_tests`
с тегом `[FlushVolCalc]` проверяет оба общих порога. Она подключается в сборках с GUI:
`FlushVolCalculator` использует `RGB2HSV` из существующей библиотеки `libslic3r_gui`.
Эта проверка не заменяет проверки пересчёта матрицы и передачи объёма в G-code ниже.

Проверять на штатном профиле Bambu Lab A1 mini с двумя физическими филаментами: обычным PLA и PETG
с `filament_is_support = true`. Установить `flush_multiplier = 1.0` и выполнить полный пересчёт матрицы.
Для проверки G-code использовать модель с переходами в обоих направлениях, например с интерфейсом
поддержек из PETG.

| Проверка | Ожидаемый результат |
| --- | --- |
| Переход PLA → PETG поддержки | В матрице 800 мм³ при разных и одинаковых цветах |
| Переход PETG поддержки → PLA | Не менее 800 мм³; цветовой расчёт выше 800 не уменьшается |
| Оба филамента отмечены как материалы поддержки | Между разными слотами 800 мм³ |
| Сброс признака поддержки у обоих филаментов | Обычный цветовой расчёт без новой нижней границы |
| Полный пересчёт, обновление филамента и расчёт CLI | Общие значения 800/800 применяются согласованно |
| Множитель 0.5 | Значение внутренней матрицы 800 отображается и используется как 400 мм³ |
| Продувка в заполнение, объекты и поддержки включена | Для переходов с материалом поддержки объём не распределяется в модель |
| Башня включена | Её объём не подменяет и не уменьшает передаваемую продувку |
| Экспорт G-code для 800 мм³ при множителе 1.0 | 758.24 мм³ в порциях продувки; 41.76 мм³ учтены при загрузке |
| Сохранение и повторное открытие 3MF | Матрица и множитель сохраняются; ручные значения не заменяются без пересчёта |

При сверке порций учитывать округление чисел в G-code, не складывать повторно `L[flush_length]`
и явные команды экструзии `G1` как два независимых объёма и не относить компенсацию подтекания или заполнение
башни к основным 800 мм³. После обновления апстрима повторять проверки поведения и передачи объёма,
даже если обе константы сохранились без конфликта слияния.
