# Контейнерный запуск тестов

## Назначение и границы

Предоставить команду `scripts/test/run.sh` для сборки и запуска тестов в том же локальном образе,
который использует контейнерная сборка. Короткая точка входа позволяет разрешить её запуск с эскалацией
без нового многострочного запроса для каждого фильтра тестов.

База апстрима: `main` репозитория <https://github.com/OrcaSlicer/OrcaSlicer.git>,
ревизия `bd1304443cb417d39c7be7d4182d8d8c1f737908`. Ветка форка: `v2.5.0-lora`.

## Контракт

- [scripts/test/run.sh][code:runner] запускается из любого каталога. Первый аргумент выбирает набор:
  `fff_print` по умолчанию, `libslic3r`, `libnest2d`, `slic3rutils`, `sla_print`, `filament_group`, `all`
  или самостоятельную проверку метаданных сборки `version`.
- Остальные аргументы передаются Catch2 без shell-интерпретации. Без аргументов исключается `[NotWorking]`.
  Например: `scripts/test/run.sh fff_print '[SupportContact]'`.
- Перед тестом собирается соответствующая цель `<набор>_tests` в существующем каталоге `build`, конфигурация
  `Release`. Для `all` собираются все перечисленные цели и вызывается штатный [run_unit_tests.sh][code:tests].
  Аргументы Catch2 для `all` не принимаются.
- Набор `version` запускает [проверки версии из ветки][doc:version] через CMake без компиляции приложения
  и без требования `build/CMakeCache.txt`. Ему нужен подготовленный контейнерный образ с CMake, Git и Ninja;
  аргументы Catch2 не принимаются. Этот набор запускается отдельно от `all`.
  Единственный необязательный флаг `--appimage` добавляет проверку версии готового AppImage через `--help`
  с временным домашним каталогом, без GUI и доступа к сети.
- Первая настройка сборки и создание образа остаются ответственностью [scripts/build.sh][code:build]
  с аргументом `-t`. Обёртка тестов не устанавливает пакеты и не загружает образы.
- `ORCA_CONTAINER_CLI`, `ORCA_DOCKER_IMAGE`, `ORCA_DOCKER_BASE_IMAGE` и `ORCA_DOCKER_CMAKE_VERSION`
  имеют тот же смысл, что в [build_linux.sh][code:upstream-build]. Автоматический тег вычисляется
  по тому же рецепту; после обновления апстрима эти вычисления необходимо сверить.
- Параллелизм сборки задаёт `CMAKE_BUILD_PARALLEL_LEVEL` или `nproc`. Ограничение времени тестового запуска
  задаёт `ORCA_TEST_TIMEOUT` в секундах, по умолчанию `600`; сборка этим временем не ограничивается.
- Контейнеры запускаются без сети и удаляются после завершения. Файлы создаются с UID/GID вызывающего
  пользователя. Каталог проекта доступен для записи результатов сборки и штатных файлов тестов.
- Полные логи `build.log` и `tests.log` остаются в отдельном временном каталоге `orcaslicer-tests.*`.
  Путь выводится до запуска; автоматического удаления логов нет. Общий прогон также создаёт
  штатный `ctest_results.xml` в корне проекта. Для `version` создаётся только `tests.log`;
  временные Git-репозитории остаются внутри контейнера и удаляются вместе с ним.
- Ошибка сборки, теста, отсутствие совпадений фильтра, тайм-аут или ошибка записи лога дают ненулевой код.
  Сборка, завершившаяся ошибкой, не сменяется запуском старого тестового бинарника.

Требуются Bash, Docker/Podman, стандартные GNU-утилиты и контейнерный образ сборки.
Для наборов Catch2 дополнительно нужна уже настроенная контейнерная сборка с тестами.
В образе нужны CMake, компилятор и `timeout`. Обёртка не меняет настройки хоста и не запускает GUI или печать.

## Перенос и проверка

Переносить точку входа вместе с карточкой. Проверять соответствие имён целей и путей тестовых бинарников
штатной конфигурации CMake, а также сохранение контракта полного прогона `run_unit_tests.sh`.

- `bash -n scripts/test/run.sh` и `shellcheck scripts/test/run.sh` завершаются успешно.
- Именованный фильтр запускает нужные тесты; полный вывод и результат доступны в сохранённых логах.
- Фильтр без совпадений и падающий тест не дают ложного успешного результата.
- Неверное имя набора отклоняется до обращения к Docker/Podman.
- Запуск из другого каталога и аргумент фильтра с пробелами сохраняют смысл команды.
- Параллелизм соответствует настройке, а тесты не выполняются при неудачной сборке.
