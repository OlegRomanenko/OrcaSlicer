# Контейнерная сборка с сохранением лога

## Назначение и границы

Предоставить короткую воспроизводимую команду `scripts/build.sh`, которую можно запускать с эскалацией
без многострочного shell-кода в запросе подтверждения. Скрипт делегирует сборку штатному `build_linux.sh`,
не заменяет его систему сборки и не устанавливает пакеты на хосте.

База апстрима: `main` репозитория <https://github.com/OrcaSlicer/OrcaSlicer.git>,
ревизия `fcd813199877fd1247c46cd6cb353bddc9ac5e6e`. Ветка форка: `v2.5.0-lora`.

## Контракт

- Публичная точка входа: [scripts/build.sh][code:runner]. Запуск возможен из любого текущего каталога.
- По умолчанию вызывается `build_linux.sh -g -dsi`: контейнер, зависимости, приложение и AppImage.
- Параллелизм берётся из `CMAKE_BUILD_PARALLEL_LEVEL`, если он задан; иначе используется `nproc`.
  Дополнительный аргумент `-j N` переопределяет этот выбор через штатный разбор аргументов.
- Аргументы передаются штатному скрипту без изменения; например, `scripts/build.sh -t` также собирает тесты.
- Docker/Podman, образ, компилятор, каталоги сборки и упаковка остаются под управлением `build_linux.sh`.
- Полный объединённый вывод сохраняется в `build.log` нового приватного временного каталога
  `orcaslicer-build.*`. Путь выводится при запуске и завершении. Логи не удаляются автоматически.
- В терминал выводятся ошибки, итог проверки AppImage, завершение и периодические строки прогресса.
- Ошибка сборки или конвейера логирования возвращает ненулевой код; сообщение об успехе появляется
  только после успешного завершения всего конвейера.
- Очистка сборки и пересоздание образа не включены по умолчанию. Переданные `-c` и `-F` сохраняют
  соответствующие побочные эффекты штатного скрипта.

Требуются Bash, `nproc`, `mktemp`, `tee`, `awk` с `systime()` и `fflush()`, а также Docker или Podman.
Скрипт создаёт лог и штатные результаты сборки; контейнерный движок может создавать образы и служебные файлы.
Для запуска из ограниченного окружения требуется разрешённая эскалация.

## Перенос и проверка

Переносить точку входа вместе с этой карточкой, сохраняя делегирование в [build_linux.sh][code:upstream-build].
После обновления апстрима проверять поддержку флагов `-g`, `-d`, `-s`, `-i`, `-j`, `-t`
и переменной `CMAKE_BUILD_PARALLEL_LEVEL`.

- `bash -n scripts/build.sh` и `shellcheck scripts/build.sh` завершаются успешно.
- При обычном запуске создаётся AppImage в штатном каталоге сборки и сохраняется полный лог.
- При запуске с `-t` дополнительно собираются тесты; сам запуск тестов остаётся отдельной проверкой.
- При ненулевом завершении штатной сборки обёртка не сообщает об успехе и сохраняет лог ошибки.
- Пути с пробелами и переданные аргументы сохраняются как отдельные аргументы shell-команды.
