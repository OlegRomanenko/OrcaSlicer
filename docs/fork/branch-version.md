# Версия сборки из имени ветки

## Назначение и границы

Показывать версию форка в интерфейсе и использовать её в имени AppImage без ручной замены строки
при переходе на следующую версию. Для ветки `v2.5.0-lora` результат — `2.5.0-lora`
и `OrcaSlicer_Linux_V2.5.0-lora.AppImage`.

База апстрима: `main` репозитория <https://github.com/OrcaSlicer/OrcaSlicer.git>,
ревизия `fcd813199877fd1247c46cd6cb353bddc9ac5e6e`. Ветка форка: `v2.5.0-lora`.

## Требуемое поведение

- Источник отображаемой версии — текущая локальная ветка Git в корне исходников.
  Поддерживается имя `vMAJOR.MINOR.PATCH` с необязательным суффиксом, например `-lora` или `-rc.1`.
  Компоненты суффикса состоят из латинских букв и цифр, разделённых точками или дефисами.
  Удаляется только начальная `v`; числовая часть и суффикс не закреплены за конкретной веткой.
- Для `main`, других неподходящих имён, `detached HEAD`, недоступного Git, его метаданных или архива без `.git`
  сохраняется штатная версия, объявленная апстримом в `version.inc`. Теги не подменяют имя ветки.
  Одноимённый тег не влияет на версию текущей ветки. Архив, распакованный внутри другого
  репозитория, не наследует его ветку.
- При доступных метаданных Git поддерживаются обычная рабочая копия и worktree. Определение версии
  не меняет ссылки Git, настройки репозитория или исходники. При повторной настройке CMake версия вычисляется заново;
  смена ветки также вызывает повторную настройку при обычной сборке уже настроенного проекта.
- `SoftFever_VERSION` остаётся общим источником для интерфейса, генерируемого заголовка и упаковки.
  `ORCA_VERSION_MAJOR`, `ORCA_VERSION_MINOR` и `ORCA_VERSION_PATCH` соответствуют выбранной версии.
  Внутренняя `SLIC3R_VERSION`, ключ приложения, каталоги настроек и форматы проектов не меняются.
- Применяются существующие шаблоны упаковки; отдельного переименования готового AppImage нет.
  Загрузка обновлений и публикация релизов не входят в доработку. Метки артефактов в GitHub Actions,
  которые читают штатную строку версии как текст, остаются отдельным механизмом апстрима.

## Компоненты и перенос

В [version.inc][code:version] после штатной версии и до выделения её числовых компонентов
определять ветку через `git symbolic-ref --quiet HEAD`, проверяя полный префикс `refs/heads/v`.
Не использовать сокращённое имя: оно зависит от наличия одноимённого тега. Обрабатывать строго подходящее имя;
значение не должно попадать в интерпретатор shell. Git необязателен: его отсутствие не блокирует сборку.
Для автоматической повторной настройки CMake отслеживать файл `HEAD`, разрешённый самим Git,
в том числе для worktree. В режиме `cmake -P` зависимости сборочной системы не регистрировать.

[Заголовок версии][code:header], [формирование отображаемой версии][code:gui]
и [шаблон AppImage][code:appimage] должны продолжать получать одно значение `SoftFever_VERSION`.
После переноса сверить эти связи и сохранить штатную резервную строку версии из нового апстрима.

[scripts/test/run.sh][code:runner] предоставляет набор `version` для автономных проверок CMake и Git
в существующем контейнерном образе. Он не компилирует приложение, не требует его настроенной сборки
и не принимает аргументы Catch2. Временные репозитории создаются только внутри тестового контейнера;
рабочая ветка проекта не переключается. Полный вывод сохраняется обычной обёрткой тестов.
Флаг `--appimage` дополнительно проверяет уже собранный AppImage: запуск `--help` без GUI
должен вывести ту же версию. Домашний каталог и файлы запуска изолируются внутри контейнера.

## Проверка

- `scripts/test/run.sh version`: ветки с суффиксом и без него дают ожидаемую версию, включая другую
  числовую версию. Неподходящие имена, `detached HEAD`, отсутствие Git и архив дают штатную версию.
- Проверка worktree даёт версию его собственной ветки. Смена ветки в тестовом репозитории обновляет
  уже настроенную сборку без ручной правки или очистки кеша CMake; одноимённый тег не мешает выбору версии.
- Генерируемые заголовок и имя AppImage совпадают с выбранной версией; числовые компоненты согласованы,
  а `SLIC3R_VERSION` остаётся штатной.
- `bash -n scripts/test/run.sh`, `shellcheck scripts/test/run.sh` и проверка Markdown проходят успешно.
- `scripts/build.sh -t` в ветке `v2.5.0-lora` создаёт
  `build/OrcaSlicer_Linux_V2.5.0-lora.AppImage`. Сведения о версии в собранном приложении содержат
  `2.5.0-lora`; проверка зависимостей AppImage проходит штатным маршрутом.
- `scripts/test/run.sh version --appimage` проверяет вывод версии из готового AppImage.
  Отсутствие файла, ошибка запуска или другая версия дают ненулевой код завершения.
