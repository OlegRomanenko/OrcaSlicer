# Обычный PLA с признаком материала поддержки

## Назначение и требуемое поведение

PLA с включённой галкой `Support material` должен оставаться обычным PLA, ровно как PETG
с той же галкой остаётся PETG. Признак назначения материала не должен подменять его физический тип.

Для `filament_type = PLA` переключение `filament_is_support` не должно менять эффективный тип
на `PLA-S` и подпись на `Sup.PLA`. В выборе материалов для поддержек и при отправке задания
должен использоваться обычный тип `PLA`. Пользовательское имя профиля при этом не меняется.

В сценарии «PETG для модели, обычный PLA для интерфейса поддержек» слот AMS с обычным PLA
должен подходить этому филаменту. Нельзя требовать обозначить катушку как
`Bambu Support For PLA/PETG` или другой специальный материал ради прохождения проверки.

## Границы и сохраняемые свойства

- Галка `Support material` остаётся включённой и сохраняется в профиле и проекте.
  Исправление не должно снимать её или игнорировать её в расчётах поддержки.
- [Расчёт продувки 800/800][fork:flushing] продолжает использовать `filament_is_support`.
  Правила множителей, назначения объёма продувки и остальные ограничения этой доработки сохраняются.
- Выбор PLA для поддержки и интерфейса поддержки остаётся доступным. Температуры, поток,
  скорости и другие параметры пользовательского материала не подменяются настройками специального филамента.
- Поведение должно быть одинаковым для пользовательского, проектного и системного профиля обычного PLA,
  с наследованием и без него. Сохранение, `detach` и повторное открытие проекта не возвращают подмену типа.
- Обратный сценарий «PLA для модели, PETG для поддержки» продолжает работать без изменений.
- Настоящий специальный материал с явно заданным типом `PLA-S` не становится обычным PLA.
  Нельзя разрешать произвольное сопоставление разных типов в AMS или считать `PLA` и `PLA-S` равнозначными.
- Правила преобразования других семейств материалов, например PA, эта карточка не расширяет.

## Реализация и перенос

`DynamicPrintConfig::get_filament_type` возвращает одновременно служебный тип и отображаемую подпись.
Обычный `PLA` возвращается как `PLA` до обработки признака поддержки и идентификатора материала;
явный `PLA-S` возвращается как `PLA-S` с подписью `Sup.PLA`. Оба результата не зависят от галки.
Пустые векторы конфигурации обрабатываются как отсутствующие значения, без обращения к `front()`.
Потребители используют результат не только как подпись:
`SelectMachineDialog::reset_and_sync_ams_list` передаёт его в сопоставление материалов.

Подмена обычного PLA по признаку поддержки запрещена в общем механизме определения типа.
Исправление только подписи в одном списке недостаточно: отображение, автоматический подбор AMS,
ручной выбор слота и тип в данных задания должны согласованно использовать `PLA`.
Не обходить проблему ослаблением проверки совместимости в `DevMappingUtil` или `AmsMapingPopup`.

Базовые профили `Bambu Support W @base`, `Bambu Support For PLA @base`
и `Bambu Support For PLA/PETG @base` явно задают `filament_type = PLA-S`.
Их наследники без собственного переопределения типа получают это значение из базы.
Изменение комплектных профилей сопровождается увеличением версии [пакета BBL][profiles:version].
Специальный тип не выводится из одной галки для любого PLA.
Идентификатор, унаследованный или скопированный обычным пользовательским PLA, не должен
сам по себе возвращать запрещённую подмену типа.

В старой отсоединённой копии или проекте сочетание явного `PLA` и признака поддержки означает PLA,
даже если копия сделана из специального профиля. Эти данные не позволяют надёжно отличить обычный
материал от специального. Если такая копия действительно описывает специальный материал,
в ней нужно явно выбрать `PLA-S`; автоматическая миграция по имени или идентификатору запрещена.

При переносе сверять все потребители вычисленного типа, а также чтение, сохранение и синхронизацию
профилей. Физический тип материала и признак поддержки должны оставаться независимыми
на всём пути до выбора слота AMS. Реальную запись настроек принтера во время проверки не выполнять
без отдельного разрешения.

## Проверки и ожидаемые результаты

1. Для обычного PLA сравнить состояния `filament_is_support = false` и `true`:
   в обоих случаях эффективный тип и подпись — `PLA`; значение самого признака различается и сохраняется.
2. В проекте с PETG и PLA поддержки проверить список `Support/raft interface`:
   материал отображается как `PLA`, а не `Sup.PLA`; назначение на интерфейс не меняет его профиль.
3. При сопоставлении этого PLA со слотом обычного PLA автоматический подбор и ручной выбор доступны.
   Специальный профиль Bambu не требуется. Несовпадающие физические типы по-прежнему отклоняются.
4. Проверить пользовательские и проектные копии, наследование, `detach`, одинаковые имена в разных
   областях и повторную загрузку `.3mf`. Ни один путь не должен восстанавливать `PLA-S` для обычного PLA.
5. Пересчитать продувку между PETG и PLA поддержки: признак поддержки продолжает включать правила
   800/800 из связанной карточки, с прежним учётом множителей. Температуры и поток PLA не изменяются.
6. Повторить обратный сценарий с PETG поддержки: тип и сопоставление остаются `PETG`.
7. Проверить настоящий специальный материал с типом `PLA-S`: он сохраняет свой тип и не сопоставляется
   с обычным PLA только ради успешной отправки. Проверить также системные специальные профили,
   затронутые явным заданием типа, включая загрузку их существующих пользовательских копий.

Автоматические проверки должны проверять возвращаемый тип, подпись и результаты сопоставления,
а не только наличие галки. Проверка GUI выполняется с отдельным каталогом данных; сетевые проверки
используют тестовое состояние AMS без изменения рабочих слотов и без запуска печати.

```bash
scripts/test/run.sh libslic3r '[FilamentSupportType],[Filament],[FlushVolCalc],[PresetSaving]' --order rand
scripts/test/run.sh slic3rutils '[DevMapping]' --order rand
```

[Проверки конфигурации][test:config] сравнивают тип, подпись, неизменность исходных параметров
и явный тип комплектных баз. [Проверки сохранения][test:saving] выполняют `detach`, сохранение
одноимённых пользовательской и проектной копий, чтение JSON и настоящий экспорт/импорт `.3mf`.
[Проверки AMS][test:ams] передают вычисленный тип в производственный `DevMappingUtil`
с синтетическими слотами `PLA`, `PETG` и `PLA-S`: совпадающий тип выбирается, другой отклоняется.
Для ручного выбора сохраняется строгое сравнение в `AmsMapingPopup::is_match_material`.
